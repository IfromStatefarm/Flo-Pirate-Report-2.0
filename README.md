# Flo-Pirate-Report-2.0
Flo pirates extension 

## Access-control setup

The extension reads user access from worksheet `gid=0` in the configured access registry. Row 1 uses these headers in columns A-M:

```text
First Name | Last Name | Middle Name | User Email | Access Level | Platforms | Password Hash | Google Drive Root Folder ID | Google Drive Root Folder Name | Foundation Log Sheet ID | Foundation Log Sheet Name | Event Config Sheet ID | Event Config Sheet Name
```

Before deploying, add at least one administrator row with access level `Admin`, platforms `all`, and a blank Password Hash. The matching Google account can claim that seeded row from Settings by entering its first name, last name, and new extension password. New accounts created in Settings are added as `Waiting_Approval` with no platform access.

Column G stores a salted PBKDF2 password hash generated by the extension. Never enter or store plaintext passwords in the sheet. The reader also accepts `Password` as the column G header. See [ACCESS_CONTROL_OUTLINE.md](ACCESS_CONTROL_OUTLINE.md) for the role matrix and rollout details.

Columns H, J, and L optionally store administrator-managed Google resource IDs. Columns I, K, and M contain the friendly names shown to the user instead of those IDs. A blank managed ID leaves that setting editable so the user can provide a personal value.

Columns A and B store the user's first and last names exactly as they should appear on report forms. If that combination is already used, account creation requests a middle name or initial and stores it in column C. If the complete first, middle, and last name is also shared, login asks the user to select their column D email before checking the password and active Google identity.

If a user forgets their password, an administrator can clear only that user's column G cell. The user can then use **Create User** while signed into the matching Google account to set a new password without changing the assigned role or platforms.
