# PDF dependency and logo paths

- `lib/jspdf.umd.min.js` is the jsPDF 4.2.1 UMD bundle from the official `jspdf@4.2.1` npm tarball (`dist/jspdf.umd.min.js`). Package integrity: `sha512-YyAXyvnmjTbR4bHQRLzex3CuINCDlQnBqoSYyjJwTP2x9jDLuKDzy7aKUl0hgx3uhcl7xzg32agn5vlie6HIlQ==`. Bundle SHA-256: `e6551fcdc32f09d6853b2c5126d18d01d9447e0da618a41a11ebeee0f6c20d54`. License: MIT, with the license text retained in the bundle header. This release fixes the maintainer's HTML output and free-text annotation injection advisories (GHSA-wfv2-pwc8-crg5 and GHSA-7x6v-j9x4-qf24). jsPDF is vendored and is therefore outside `npm audit`'s dependency graph.
- The local intelligence briefing is generated by `utils/pdf_gen.js::generateIntelligencePDF`. `background/main.js` supplies the runtime theme, whose `logoDataUrl` can come from a versioned local cache or a remote customer asset resolved by `services/theme_asset_service.js`. This path can receive customer GIF logos.
- The ordinary server evidence report is generated by `server/report_pdf.js::generatePDF`, called through `server/customer_api_service.js` and `server/postgres_repository.js`. The current repository caller supplies product, colors, and legal identity without `logoDataUrl`; the renderer's optional logo path is guarded in case a future caller supplies one.
- Both renderers call `utils/pdf_logo.js::validatePdfLogo` before `addImage`. It requires a PNG, JPEG, GIF, or WebP data URL with matching header; limits source bytes to 1 MiB; limits each edge to 2048 pixels and decoded RGBA allocation to 16 MiB. GIF frame descriptors, canvas bounds, frame count, and cumulative frame pixels are checked before jsPDF receives the image. An invalid logo is skipped while the PDF still renders.

Verification: `node --test tests/pdf_logo_security.test.mjs tests/report_pdf.test.mjs` exercises valid logo embedding, hostile GIF headers and frame dimensions, oversized inputs, both PDF routes, and report layout across page boundaries.

Dependency remediation verified on 2026-10-02: the lockfile resolves `hono@4.13.12`, `@hono/node-server@2.1.3`, `brace-expansion@5.0.12`, `diff@5.2.2`, and `neon@4.22.0`. Both `npm audit` and `npm audit --omit=dev` reported zero affected packages. All six functions declared in `neon.ts` produced nonempty `index.mjs` ZIP bundles using `@neon/config-runtime`'s `buildFunctionBundle`. The extension ZIP contained the inventoried jsPDF bundle and no Neon CLI or server packages. These checks validate local release inputs; a live Neon deployment was not performed.
